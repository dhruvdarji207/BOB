About

How CarPriceAI works — methodology, architecture and limitations.

What Is This Application?

CarPriceAI is a machine-learning-based car price prediction system. Given a set of vehicle specifications — such as engine size, horsepower, body style and manufacturer — the application uses a trained regression model to generate an estimated selling price.

The system is built on a real automotive dataset containing 205 records and 24 predictive features. It is not a lookup table; every prediction is computed live by the ML model.

Important: Predictions are estimates based on historical dataset patterns. They do not represent actual current market prices, which depend on depreciation, location, negotiation and many other factors not captured in this dataset.

How It Works

1

User Input

You fill in vehicle specifications on the Predict page: manufacturer, engine size, horsepower, body style, dimensions, fuel efficiency and more.

↓
2

Data Validation

The Flask backend validates all fields — required fields, numeric ranges, and categorical value membership.

↓
3

Preprocessing

The same scikit-learn preprocessing pipeline used during training is applied to your input: StandardScaler for numerics, OneHotEncoder for categoricals.

↓
4

Machine Learning Model

The preprocessed feature vector is passed to the best-performing regression model selected during training (e.g. Random Forest or Gradient Boosting).

↓
5

Price Prediction

The model outputs a predicted price in USD based on learned patterns from the training data.

↓
6

Result

The predicted price is returned as JSON and displayed instantly in the browser — no page reload required.

Machine Learning Methodology

Model Selection

Six regression algorithms are trained and evaluated:

  • Linear Regression — Baseline model
  • Ridge Regression — L2 regularized linear model
  • Random Forest Regressor — Ensemble of decision trees
  • Gradient Boosting Regressor — Sequential boosting ensemble
  • Extra Trees Regressor — Extremely randomized trees
  • HistGradientBoostingRegressor — Histogram-based gradient boosting

Evaluation Metrics

  • R² — Proportion of variance explained (closer to 1 is better)
  • MAE — Mean Absolute Error in dollars
  • RMSE — Root Mean Squared Error (penalises large errors)
  • 5-Fold CV R² — Cross-validated R² to assess generalisation

Data Leakage Prevention

  • price is never used as an input feature
  • car_ID is dropped (not predictive)
  • Preprocessing (scaler, encoder) is fitted only on training data
  • The complete fitted pipeline is saved — inference uses the exact same transformations

Limitations

  • Trained on only 205 records — a larger dataset would improve accuracy.
  • The dataset is from an older era; modern vehicles may have very different pricing dynamics.
  • Geographic factors (taxes, import duties, regional demand) are not captured.
  • Condition, mileage and maintenance history are not included in the features.
  • The model extrapolates poorly for car specifications very different from the training distribution.
  • Currency conversion is not performed — all prices are in the dataset's original units (USD).
